# D2.nvim 開發理念與原則

## 🎯 核心開發理念

### KISS 原則至上

**Keep It Simple, Stupid** 是本專案的最高指導原則，體現在：

#### 架構設計中的 KISS

- **模組化設計**：每個模組單一職責，介面清晰
- **最小依賴**：只引入必要的依賴，優先使用 Neovim 內建功能
- **漸進式功能**：從 MVP 開始，逐步添加功能
- **配置簡化**：提供合理預設值，零配置即可使用

#### 程式碼實現中的 KISS

- **函數職責單一**：一個函數只做一件事
- **變數命名清晰**：避免縮寫和模糊命名
- **邏輯流程直觀**：優先可讀性而非過度優化
- **錯誤處理簡潔**：提供明確的錯誤訊息和處理路徑

#### 用戶介面中的 KISS

- **命令統一**：使用 `:D2` 前綴的一致命令結構
- **按鍵直觀**：預設按鍵綁定符合直覺
- **狀態透明**：清楚顯示操作狀態和結果

## 🔧 技術實現原則

### 1. CLI 工具最大化利用

**核心思想**：不重新發明輪子，善用 D2 CLI 現有功能

#### 功能對應策略

```
Neovim Plugin 功能    →    D2 CLI 對應
==========================================
即時預覽             →    d2 --watch
多格式導出           →    d2 [file] --format
語法檢查             →    d2 compile
程式碼格式化         →    d2 fmt
主題切換             →    d2 --theme
```

#### 實現原則

- **包裝而非重寫**：提供便利的 Neovim 介面包裝 CLI 功能
- **非同步優先**：所有 CLI 操作使用非同步執行避免阻塞
- **錯誤轉譯**：將 CLI 錯誤轉譯為 Neovim 診斷格式
- **狀態管理**：適當追蹤 CLI 進程狀態

### 2. Tree-sitter 優先策略

**核心思想**：最大程度利用 Neovim 的 Tree-sitter 生態系統

#### 功能實現優先順序

1. **語法高亮**：使用 tree-sitter queries 而非正則表達式
2. **程式碼導航**：基於語法樹的精確導航
3. **智慧縮排**：根據語法結構的自動縮排
4. **程式碼折疊**：語法感知的折疊邏輯
5. **符號搜索**：基於語法節點的符號提取

#### Tree-sitter 整合策略

```lua
-- 優先使用 tree-sitter 功能
if vim.treesitter.get_parser(bufnr, 'd2') then
    -- 使用 tree-sitter 實現
    return treesitter_implementation()
else
    -- fallback 到傳統方法
    return fallback_implementation()
end
```

### 3. 參考專案學習原則

#### 從 tmux-send.nvim 學習

- **模組化架構**：清晰的模組分工和介面設計
- **配置系統**：豐富但有理的預設值
- **非同步處理**：CLI 整合的最佳實踐
- **測試覆蓋**：完整的單元測試和整合測試

#### 從 aider.nvim 學習

- **工作流程整合**：無縫的編輯器和工具整合
- **狀態管理**：適當的狀態追蹤和持久化
- **用戶體驗**：直觀的命令和回饋機制

## 🚀 開發實施原則

### 漸進式開發策略

#### Phase 1: MVP (Minimum Viable Product)

**目標**：提供基本可用的功能

- [x] 基本語法高亮（tree-sitter）
- [x] 即時預覽功能（d2 --watch）
- [x] 基本導出功能（d2 export）
- [x] 檔案類型識別

#### Phase 2: 核心功能完善

**目標**：提供完整的編輯體驗

- [ ] 錯誤診斷和提示
- [ ] 程式碼格式化（d2 fmt）
- [ ] 主題切換功能
- [ ] 智慧縮排和折疊

#### Phase 3: 高級功能

**目標**：提供專業級別的開發體驗

- [ ] 自動完成功能
- [ ] 程式碼片段支援
- [ ] 符號導航和搜索
- [ ] 整合其他工具（如 telescope）

### 品質保證原則

#### 測試策略

- **測試驅動開發**：關鍵功能先寫測試
- **多層次測試**：單元測試 + 整合測試 + 端到端測試
- **持續整合**：自動化測試和品質檢查

#### 程式碼品質

- **靜態分析**：使用 selene 進行 Lua 程式碼檢查
- **格式化**：使用 stylua 保持程式碼格式一致
- **文檔完整**：每個公開 API 都有完整文檔

### 相容性考量

#### Neovim 版本支援

- **最低版本**：Neovim 0.9+
- **推薦版本**：Neovim 0.10+（更好的 tree-sitter 支援）
- **未來相容**：跟隨 Neovim 發展趨勢

#### 跨平台支援

- **主要平台**：Linux, macOS, Windows, WSL
- **路徑處理**：使用 Lua 標準庫處理路徑差異
- **命令執行**：適配不同平台的命令執行差異

## 🎨 用戶體驗原則

### 零配置哲學

#### 合理的預設值

```lua
-- 範例：預設配置展示 KISS 原則
local defaults = {
    -- 簡單但完整的預設配置
    cli_binary = "d2",        -- 假設 d2 在 PATH 中
    auto_preview = false,     -- 不要太激進
    preview_theme = "default", -- 使用 D2 預設主題
    export_format = "svg",    -- 最通用的向量格式
}
```

#### 漸進式配置

- **Level 0**：零配置，直接使用
- **Level 1**：基本配置，調整常用選項
- **Level 2**：進階配置，自定義工作流程
- **Level 3**：專家級配置，完全自定義

### 一致的命令介面

#### 命令命名規範

```vim
:D2Preview [file]     " 預覽功能
:D2PreviewStop        " 停止預覽
:D2Export [format]    " 導出功能
:D2Format             " 格式化
:D2Theme [theme]      " 主題切換
:D2Compile            " 語法檢查
```

#### 按鍵綁定一致性

```lua
-- 統一使用 <leader>d 前綴
local keymap_prefix = '<leader>d'
local keymaps = {
    p = 'preview',    -- <leader>dp
    s = 'stop',       -- <leader>ds
    e = 'export',     -- <leader>de
    f = 'format',     -- <leader>df
    t = 'theme',      -- <leader>dt
    c = 'compile',    -- <leader>dc
}
```

### 透明的狀態回饋

#### 操作狀態顯示

- **進行中**：清楚顯示正在執行的操作
- **成功**：簡潔的成功訊息和結果路徑
- **錯誤**：明確的錯誤訊息和建議解決方案

#### 非阻塞式互動

- **背景執行**：長時間操作不阻塞編輯
- **進度指示**：適當的進度顯示
- **可取消操作**：提供取消長時間操作的方式
